## 截图

```bash
CHROME="/c/Program Files/Google/Chrome/Application/chrome.exe"
"$CHROME" --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=10000 \
  --window-size=<画布宽>,<画布高> \
  --screenshot=<输出.png> \
  "http://localhost:3000/<路由>"
```

- `--virtual-time-budget=10000` 必须给够，ECharts 要时间渲染，给小了截出来是空白
- `--window-size` 要**等于页面的设计画布尺寸**，这样 `ScreenScaler` 的缩放比接近 1，截出来和设计稿基本 1:1
- **不要加 `--force-device-scale-factor=1`**。加了之后所有 ECharts 只画坐标轴、不画图形，
  很容易被误判成代码 bug（已复现确认与业务代码无关）。
- 实测窗口高度会被浏览器自身占掉几十像素，`ScreenScaler` 实际缩放约 0.92 而非 1。
  **比对分栏比例没问题，但不要拿绝对像素值去量。**

各页画布尺寸：

| 页面 | 路由 | 画布 |
|------|------|------|
| 全景座舱（首页） | `/` | 3540 × 940 |
| 任务调整 / 政策分析 | `/task-adjust` `/policy-analysis` | 2400 × 1080 |
| 模块平台页 | `/platform/<key>` | 2400 × 1080 |

## 比对

用 Read 工具同时读「你截的图」和「`_refs/live/` 里的参考图」，逐块对位置、尺寸、层级、配色。
**不要只看整体像不像**，要逐个面板核对：分栏比例、面板标题、子区块排列、图表类型与坐标轴。

## 常见坑（都踩过）

1. **图表塌成 0 高**：`PanelBox` 的内容区已带 `flex-1`，但你自己写的嵌套容器若缺 `min-h-0`，
   flex 子项仍会被内容撑开导致溢出或塌陷。链路上每一层都要 `min-h-0 flex-1`。
2. **图表只剩坐标轴没有图形**：`useChartColors()` 的返回值已用 `useMemo` 固定引用；
   但如果你自己又在渲染期构造新对象传进 `useMemo` 依赖，动画会被反复打回起点。
3. **ECharts 解析不了 `var()` 和 `color-mix()`**：canvas 渲染只认具体色值，
   必须经 `useChartColors()` 取色；要透明度就用工具函数把 `#rrggbb` 转 rgba。
4. **SVG 的 `<linearGradient>` / `<clipPath>` id 撞车**：不要用中文标签生成 id
   （中文在 JS 正则里属于 `\W`，`replace(/\W/g,'')` 会把整条抹成空串，多个图形拿到相同空 id 互相覆盖）。
   用 React 的 `useId()`。
